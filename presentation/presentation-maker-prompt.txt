AGENTCITY TWIN PRESENTATION BRIEF

Create a polished 16:9 presentation for a mixed audience of city planners, campus operators, technical judges, and prospective pilot partners. Plan for eight minutes of presentation and five minutes of questions. Use English. Lead with the Debrecen case and show the product through genuine screenshots.

Deliver a self-contained LaTeX Beamer source file called agentcity-twin.tex and a compiled PDF called agentcity-twin.pdf. Embed a short speaker note for each frame with \note{...}. Also deliver a notes-view PDF or a separate readable notes document, and a plain-text question and answer sheet with concise responses. Put all files in the supplied presentation folder. Keep all asset paths relative to that folder.

Use demo-evidence.json as the source of numerical claims, scenario details, strategy names, and advisory provider receipts. The metrics in that file come from a recorded simulation. Use the companion speaker-notes.txt and questions-and-answers.txt as a starting point. Credit OpenStreetMap contributors where the basemap appears.

Visual direction

Use an editorial city-planning look with warm off-white #F6F4EC, ink #10273B, teal #006659, and a deep blue #16324D results slide. Use large, readable typography and generous margins. Make maps and evidence the focus on the slides that use them. Use a two-column layout only when both columns can be read comfortably from a distance. Put the dense screenshots on full-width frames or crop to the relevant area and retain any important labels and attribution. Use one composition per frame and display essential values as editable LaTeX text. Keep screenshot proportions with \includegraphics[width=\linewidth,height=.65\paperheight,keepaspectratio]{...}. Use \linewidth and relative column widths so the source adapts to 16:9 or 4:3 if the aspect ratio is changed. The compiled PDF has a fixed canvas. The separate responsive version in index.html is available for small screens.

Frame sequence

1. Introduce AgentCity Twin in one sentence. Use assets/screenshots/02-forecast.jpg as the main visual.
2. Introduce the 17:00 university corridor accident and why a planner needs to compare options. Use assets/screenshots/01-workspace.jpg.
3. Explain the workflow from scenario inputs to specialist findings, network simulation, scoring, and operator review. Use a short sequence with one sentence per stage.
4. Show the simulated baseline versus recommended response at +30 minutes. Use assets/screenshots/03-comparison.jpg and reproduce the key values from demo-evidence.json in editable text. Clearly state the units and reference point.
5. Explain how specialist disagreement triggered a second simulation. Use assets/screenshots/04-explanation.jpg. State which strategy ranked first after the second pass and use the exact simulated scores.
6. Show how a reviewer can trace the recommendation. Use assets/screenshots/05-audit.jpg. Explain verification and the human review step succinctly.
7. Explain the architecture and the role of local inference. Use assets/screenshots/06-model-lab.jpg. Docker hosts the API, worker, and PostgreSQL/PostGIS. LM Studio serves the configured local models. The network solver produces the metrics and ranking.
8. Close with the pilot scope and Q&A. Explain what a city or campus would supply to test the approach on local data.

Optional jury appendix

Use scenario-evidence.json for four additional recorded cases. Each record includes the forecast and comparison filenames under assets/screenshots. Build one optional frame per case, with a map, the selected intervention, and the baseline and recommended values for its highlight metric at +30 minutes. Use the tram case to discuss a closed diversion option, stadium departures for crowd-related demand, air quality for modeled emissions, and essential services for modeled energy load. Keep these frames outside the eight-minute sequence.

Speaker notes

Write short spoken paragraphs for every slide, with rough timing, what to point at, and one natural transition. Budget the eight minutes across the eight slides. Include a short live walkthrough and a fallback using the recorded screenshots if the demo cannot connect. Keep notes out of the audience PDF.

Likely questions

Prepare direct answers about data provenance, calibration, deterministic versus model-generated output, strategy negotiation, human approval, handling model outages, privacy, supported feeds, reproducibility, scalability, and the evidence required for a municipal pilot. Avoid invented partners, measured benefits, unsupported production guarantees, and fabricated screenshots. Label simulated results visibly on the relevant slides. Confirm the deck compiles, verify every screenshot exists, and inspect all slides for clipped content and readable labels before delivering.
